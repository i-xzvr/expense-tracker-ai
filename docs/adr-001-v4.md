# ADR-001: V4 local application, agent service and export adapters

Status: Accepted for implementation. Date: 2026-10-10.

## Context

V3 is a working local bookkeeping app with deterministic calculations, browser financial storage, SQLite chats and optional Ollama AI. The user requests all course export features, real server APIs, a coding agent and useful cloud connections while preserving V3.

## Decision

Keep Next.js route handlers for product APIs. Add a separate loopback coding-agent HTTP process with durable jobs, bounded events, cancellation and isolated Git worktrees. Use the repaired Claude CLI with the existing local login; do not expose it as a public multi-user service. Keep finance inference on Ollama. Add server-generated PDF and export metadata, explicit captured snapshots for schedules/shares, and provider adapters for connected delivery. Provider credentials remain server-side.

Retain port 3103 for the product so existing browser IndexedDB data remains available. Preserve the financial schema and storage names. New V4 operational metadata goes into separate SQLite storage; existing chats remain intact. Every external delivery requires a selected destination and explicit user action or saved schedule. Schedules export the captured snapshot, not unseen future browser edits.

## Options considered

| Option | Complexity | Benefits | Costs |
| --- | --- | --- | --- |
| Replace V3 with a hosted cloud app | High | Remote access | Authentication/storage migration; data exposure; avoid for this release |
| Only add cloud export buttons | Medium | Immediate delivery | Does not implement course coding-agent server |
| Local product + separate agent + adapters | Medium | Preserves data/AI and implements course architecture | Two process lifecycles; live cloud requires account configuration |

## Consequences

PDF uses the same deterministic report snapshot as CSV/JSON. Jobs cannot silently modify the active project. Job worktrees are not OS sandboxes; Claude's restricted file mode and removal of command/network tools limit execution, but Windows native Claude has no OS sandbox. Changes are presented as diffs for review. Secrets, financial data and private chat database are excluded from worktrees. Generated shares are local, expiring links; a QR code does not make localhost reachable from another device. No public deployment is implied.

## Build sequence

1. Verify platform; repair Claude; branch and back up V3.
2. Shared API validation/contracts; server PDF; custom filters/filename/templates/history.
3. Combined portability and chat merge; isolated browser acceptance.
4. Persistent coding-agent jobs, real CLI adapter, result/cancellation UI.
5. Cloud export adapters, scheduling captured snapshots, local sharing/email handoff.
6. Monthly Insights and AI selection assistance; final quality/live verification.
